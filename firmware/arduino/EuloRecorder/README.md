# Arduino ESP32 / STM32 sensor recorder (NOT flight firmware)

`EuloRecorder.ino` is one real Arduino sketch for **Arduino-ESP32 and STM32duino**. It has three explicitly selected roles: serial BMP388/BMP390 + LSM6DSOX recording; the same recording with *opt-in* SX127x LoRa transmit; or a separate SX127x receiver forwarding accepted packets to serial. It never outputs PWM, ignites a motor, commands a servo, provides GPS, or controls flight. Its **checked-in configuration reads no sensors and transmits no RF**. There is no identified user board, module, wiring diagram, instrument trace or hardware log in this repository.

## Identify before flashing

1. Record your exact ESP32 or STM32 **board variant**, Arduino core and flash/serial port; the exact BMP388/BMP390, LSM6DSOX and optional SX1276/77/78/79 radio modules; their I²C addresses; voltage, logic levels, SDA/SCL pins, radio SPI pins, CS/RESET/DIO0, antenna, supply and a common ground. Consult each board's schematic. **Do not guess pins from an unrelated development board.** A radio must have a suitable antenna before it is powered/transmitting. Keep motor/igniter and actuators disconnected during bring-up.
2. Install the matching Arduino-ESP32 or STM32duino core in Arduino IDE/CLI, and the Arduino libraries **Adafruit BMP3XX Library 2.1.6**, **Adafruit LSM6DS 4.7.4**, and **LoRa 0.8.0** (only needed for radio modes). These are candidate driver families, **not a claim that the user owns these sensors**. CI uses Arduino-ESP32 3.3.7 and STM32duino 3.1.0 and compiles two *representative* FQBNs; verify the versions and the core's actual USB and pin mappings for your board. See the compile-only job in `.github/workflows/build.yml`.
3. In `hardware_config.h`, set `EULO_BOARD_REVIEWED=1`, `EULO_WIRE_PINS_REVIEWED=1`, observed `EULO_PRESSURE_ADDRESS` (0x76 or 0x77) and `EULO_IMU_ADDRESS` (0x6A or 0x6B) **only after** reviewing the selected board variant's default `Wire.begin()` SDA/SCL pins. For a STM32 or ESP board with nondefault I²C pins, change the sketch's `Wire` setup for the *actual variant* and test it. The sketch probes both sensors; on failure it prints an error and **does not invent samples**. Default `EULO_LOG_PORT` is `Serial` at 115200; on STM32 this might be a UART, not USB. Select a real `SerialUSB` port in the config only if your chosen STM32 core/variant provides and enables it. Native USB CDC/USB-Serial-JTAG choices on ESP32 likewise depend on the board and Arduino menu options. Never block on `while(!Serial)` for unattended logging.
4. First validate on a stationary table with actual power/serial wiring. Check WHO_AM_I detection, pressure against a reference instrument, ~1 g acceleration magnitude at rest, gyro rates after a measured rotation, timing, disconnect/reconnect behaviour, and the first two stationary seconds. The sketch logs **raw pressure Pa, temperature °C, gyro deg/s and acceleration m/s² at 20 Hz**. It stops after a sensor error, one hour, or 12,000 emitted rows (whichever comes first). No sensor data is in the repository; unit-test numbers in `tests/` are synthetic and never presented as measurements.

### Obtain a recording from the physical port

On the **computer connected to your identified board**, install `pyserial` (not needed for `make test`), then run from the repository root:

```sh
python3 -m pip install pyserial
python3 tools/capture_serial.py --port YOUR_OBSERVED_PORT --output out/recording.csv --seconds 120 --board-label YOUR_OBSERVED_BOARD
```

The port and board label above are **placeholders, not actual device IDs**. This tool sends only the read-only serial handshake `H`. It requires the sketch banner, exact nine-column units, finite and increasing timestamps, and at least two rows; it aborts rather than filling missing samples. It writes `out/recording.csv` and an adjacent `.meta.json` with port, operator-entered label, capture time, row count, gaps and SHA-256. The metadata is a trail of a *serial read*, **not authentication of a physical sensor**. Use a new filename if one exists; do not overwrite earlier evidence. Radio receiver logging requires `--seconds` long enough to catch at least two sparse packets.

In the native app: `Ground → File > Load recorded CSV` / `Ctrl+L`; place `recording.csv` alongside `project.eul`, or upload the CSV through the host preview's picker. Select **Calibrate first 2 s** only if stationary readings are present. The v2 CSV header is:

```text
time_s,pressure_pa,temperature_c,gx_deg_s,gy_deg_s,gz_deg_s,ax_m_s2,ay_m_s2,az_m_s2
```

The inspector displays raw pressure, temperature, acceleration and gyro. Calibration takes the **observed mean pressure** as the reference and computes a **relative barometric height difference** via the standard-atmosphere approximation `44330 * (1 - (pressure/reference)^0.190294957)`. This is *not* altitude above sea level or independently verified flight height; pressure ports, wind, temperature and motion affect it. Gyro-only integrated sensor-axis orientation drifts and is suppressed after a missing-sample interval >250 ms. No rocket mesh is drawn over the sensor frame; it would falsely imply the sensor was installed in that exact vehicle. The legacy five-column altitude/gyro CSV remains importable but is marked an unverified user file. The console app does **not** stream sensors or serial from the board; copy a vetted CSV to `/data/eulolab/recording.csv` for offline import if using a console.

## Optional SX127x point-to-point LoRa (NOT LoRaWAN / mesh)

Only after identifying actual radios, pins and regulatory conditions, configure *both* modules with matching `EULO_RADIO_FREQUENCY_HZ` (never preselected in this repository), `EULO_RADIO_SS`, `EULO_RADIO_RESET` and `EULO_RADIO_DIO0`, plus reviewed default SPI pins. Set transmitter `EULO_RADIO_MODE=1`, `EULO_ALLOW_RF_TX=1` and your reviewed `EULO_RADIO_TX_POWER_DBM` (the sketch accepts 2–14 dBm, which **does not prove compliant EIRP**). Set a second board to `EULO_RADIO_MODE=2` to receive; the receiver requires no sensors but **does require its own reviewed board, SPI pins, supply and antenna**. Default mode is serial-only: zero RF output. The SX127x library calls use LoRa CRC, SF7, 125 kHz, CR4/5 and a 44-byte versioned, checksummed, little-endian packet with sequence and only quantised *observed* fields. The receiver checks CRC, version, range and monotonic sequence/time, reports gaps and link RSSI/SNR, and forwards original values to serial. It does not fabricate samples or retransmit missing packets. Radio-only logs are **sparse (at most one packet per 60 s)** and will generally lack the first two seconds of stationary calibration readings; they cannot support the app's gyro-relative-attitude workflow. Use the local 20 Hz serial log for that.

A 60-second minimum interval is **not regulatory approval**. Review airtime, antenna gain, EIRP, duty cycle, coexistence and allowed ground/airborne use for your **actual region, band, equipment and test**. For the UK, [Ofcom IR 2030](https://www.ofcom.org.uk/siteassets/resources/documents/spectrum/interface-requirements/ir-2030.pdf) lists conditions by sub-band; it is not a blanket licence for every frequency or configuration. No RF testing, range testing or legal assessment has been performed. This protocol has **no encryption or authentication**; do not use it to command actuators or trust received data for safety decisions.

## Separate from the EuloBench/2 servo USB protocol

The `.ino` here is a **data recorder**, *not* a replacement for the PS4 Bench vendor-bulk firmware. The host requires USB interface `FF/45/55` with bulk IN/OUT, a physical interlock and reviewed PWM hardware. Upstream Arduino ESP32 `USBVendor` uses TinyUSB's `TUD_VENDOR_DESCRIPTOR` with **subclass/protocol `00/00`** (confirmed in core source), so merely instantiating `USBVendor` is **not compatible**. STM32duino's `SerialUSB` is CDC with DTR gating, **not** that vendor interface. The existing ESP-IDF reference and STM32 policy adapter also lack hardware/console verification; they are not `.ino` firmware. A separately engineered and instrumented Arduino vendor-bulk bench port for each identified board is still needed before any servo claim. See `docs/bench-usb.md`.
