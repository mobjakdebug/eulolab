# STM32 port of the EuloBench/2 board policy

`bench_port.{hpp,cpp}` is a **compiled and host-tested device-side port**, not a flashable STM32Cube project. It is useful for STM32 MCUs with native USB device support and timer/PWM outputs. There is no universal STM32 pinout or USB descriptor: choose a specific MCU/board, approved USB VID:PID, clock tree, available timer channels, gate input and supply wiring before producing firmware for it. A USB-to-UART adapter or arbitrary existing STM32 firmware does not implement EuloBench.

The app's **Bench → Configure USB and pin map** screen chooses a board family, authorized USB ID, vendor-interface number, expected bulk IN/OUT addresses (or descriptor-validated Auto), and the four *logical axis → approved pin* assignments. STM32 port/pin codes are hex `(port A=0 ... H=7) << 4 | pin 0..15`: `PA0 = 00`, `PB10 = 1A`, `PH15 = 7F`. The gate pin is fixed by the firmware; allowing USB to change the physical interlock would defeat its purpose. The application cannot grant new hardware PWM capability or choose a board's USB VID/PID for it; those must already be provisioned in its firmware.

## To integrate with a specific STM32 board

1. In that board's USB stack, expose exactly one EuloBench vendor interface, `bInterfaceClass FF`, `bInterfaceSubClass 45`, `bInterfaceProtocol 55`, alt setting 0, with one bulk OUT and one bulk IN endpoint. Full-speed endpoints have 64-byte max packets; the standard 32-byte reference configuration descriptor is in `firmware/esp32s3/main/main.cpp`. Use only USB IDs assigned to/authorized for your board. The Orbis adapter checks the actual descriptor and refuses a different interface/endpoint or a second matching device.
2. Provision **four to eight reviewed PWM-capable pins** as neutral 50 Hz outputs, plus one distinct physical enable input pulled LOW by default. Construct `bench::Capabilities` with `family=2`, `gatePin` and the allowed pin list; encode pins as above. Avoid USB pins, boot straps, flash/oscillator pins, inaccessible timer pins and all circuitry on the particular board. `stm32::Port` refuses a duplicate/gate pin, and the host additionally checks the list, but **only the board integrator can validate the electrical design**.
3. Implement `stm32::Hardware` with `gateClosed()` reading the physical input; `setPwmMicroseconds(pin,width)` writing the actual timer CCR for a calibrated 20,000 µs period; and `writeBulkIn(frame,length)` queueing a USB bulk response. Initialize PWM outputs to neutral **before** accepting USB. Queue OUT bytes and mount/suspend events from USB IRQ and pass them to `Port::onBulkOut`/`onUsb` **serially in task context**. Split chunks to <=64 bytes. Call `Port::tick(HAL_GetTick())` every ~10 ms even when the host sends nothing; a separate MCU hardware watchdog and physical servo-power cut-off are still needed. `onUsb(false)` immediately requests neutral and invalidates the pin map.
4. With the rig empty and linkage disconnected, verify USB descriptors, allowlist rejection, pulse widths at every provisioned pin, gate transitions, 150/300 ms deadlines, detach/suspend, timer rollover and MCU reset with instruments **before attaching a powered servo**. The protocol response is a receipt, not position feedback.

The independent, shared `bench::Board` state machine is linked from `src/core/bench_board.cpp`. `make test` compiles and runs `tests/stm32_port_tests.cpp` against a fake HAL to verify mapping, byte-fragmented USB, neutral and timeout. This does **not** compile an STM32 MCU image, exercise STM32 HAL/TinyUSB, test console USB permissions or prove that a servo moved. See [`docs/bench-usb.md`](../../docs/bench-usb.md) for the wire contract and physical bench precautions.
