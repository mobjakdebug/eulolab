# EuloLab workbench direction

## Design read

The work is a desktop-like engineering **workbench**, not a game menu, a Windows binary, or a launch planner. The core loop is **select part → change a bounded property → inspect geometry and approximate mass → inspect a calculated 3-D run**. The Ground page is for an imported recording; the USB servo bench is a separate, deliberate workflow. Both mouse/keyboard and PS4 controller actions must reach the same C++ model and command surfaces.

Dials: **ENERGY 1 / RHYTHM 2 / MOTION 1**. One visual accent, quiet measured typography, and motion only for camera navigation and deliberately started playback.

## Composition and identity

- At 1280 × 720, the shell has a conventional menu and toolbar above **a 244 px assembly/source pane, 716 px measured viewport plus analysis dock, and 320 px inspector**. The viewport has the most room; the 9-field fin section is still visible without a hidden control. The status strip carries actionable errors and a model/bench disclaimer.
- Matte paper and cool slate, with **blue only for selection, editable focus, centre-of-mass witness marks and calculation traces**. Borders delineate editor fields and overlays, not a grid texture. Space Grotesk is licensed and rasterised locally. The recurring motif is the **measured vertical silhouette, datum and unit annotations**; flight altitude shown in the viewport is explicitly symbolic, while measured model figures are in the inspector/graph.
- Bench deliberately replaces the trajectory graphic with four labelled, neutral-datum channel rows. It cannot display a live position, so the copy says **command channel / not measured position**. A separate default-cancel modal labels the exact axis, angle and duration. A visible neutral action and controller shortcut remain available over the modal. There is no fake live dashboard or simulated sensor on Bench or Ground.

## Functional contract

- **52 editable properties across 9 sections** have one real `Rocket` state behind UI, file and renderer. Model validation rejects impossible ranges and dependent fit; undo/reset operate on that model. The custom insert is a coaxial cylinder/tube, not general-purpose CAD. The linked OBJ/ASCII-or-binary-STL reference is rendered as a visual comparison only and never contributes to mass or flight. The `.eul` version-2 file links a fixed-name sibling mesh, so missing external files must be reported rather than silently invented.
- Approximate open-loop three-dimensional translation, orientation and angular rate support horizontal range, tilt/heading, wind, fixed gimbal assumptions, Mach, camera presets and timeline scrubbing. The reference drag, fin normal force, CP and damping are **not measured**. This model never commands an actuator. Recorded CSV gyro/altitude uses a stationary-window bias/zero and integrates a **relative**, drifting attitude; it is not a live board connection.
- The manual Bench page can call only an injected `BenchControl`. The host preview injects **none**; the Orbis target injects a VID/PID-pinned USB adapter when its module starts. The page never auto-connects. Its physical gate, fixed ±2°/150 ms UI, separate confirmation, board-local time cap and independent-power-cut warning are purposeful friction. Navigation out, controller loss and protocol failure close the link; the device must implement a neutral watchdog independently of PS4. A matching ACK is receipt, not observed travel or safety.
- Numeric fields allow host typing and Enter/Esc, +/- and D-pad stepping; PS4 does **not** open an unusable keyboard. Save/load has a default-cancel unsaved-change guard. Menus, toolbar, tree selection, inspector, viewport controls, recorded-data scrubbing and Bench controls have keyboard/controller/mouse paths. The host browser is a **thin framebuffer/event/file transport**; it does not reimplement physics, UI or Orbis USB.

The [`anti-slop`](https://github.com/miqdadbadjuber/anti-slop) skill (including UI and code guidance) was used **during development**: the design read preceded implementation, techniques were justified by the work, then native hitbox/keyboard/controller and HTTP round-trip tests and rendered-frame inspections checked the actual controls. The static frame is 1280 × 720; this does not imply Orbis screen-reader integration or a console-runtime test. Evidence and unresolved boundaries: [`docs/workbench-audit.md`](docs/workbench-audit.md).
