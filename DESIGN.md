# EuloLab workbench direction

## Design read

The work is a desktop-like engineering **workbench**, not a game menu, a Windows binary, or a launch planner. The core loop is **select part → change a bounded property → inspect geometry and approximate mass → inspect a calculated 3-D run**. The Ground page is for an imported recording; the USB servo bench is a separate, deliberate workflow. Both mouse/keyboard and PS4 controller actions must reach the same C++ model and command surfaces.

Dials: **ENERGY 1 / RHYTHM 2 / MOTION 1**. One visual accent, quiet measured typography, and motion only for camera navigation and deliberately started playback.

## Composition and identity

- At 1280 × 720, the shell has a conventional menu and toolbar above **a 244 px assembly/source pane, 716 px dimensional viewport plus analysis dock, and 320 px inspector**. The viewport has the most room; the 9-field fin section is still visible without a hidden control. The status strip carries actionable errors and a model/bench disclaimer.
- Matte paper and cool slate, with **blue only for selection, editable focus, centre-of-mass witness marks and calculation traces**. Borders delineate editor fields and overlays, not a grid texture. Space Grotesk is licensed and rasterised locally. The recurring motif is the **model silhouette, datum and unit annotations**; flight altitude shown in the viewport is a prediction, while the inspector/graph shows calculated model values, not measurements.
- Bench deliberately replaces the trajectory graphic with four labelled, neutral-datum channel rows. It cannot display a live position, so the copy says **command channel / not measured position**. A separate default-cancel modal labels the exact axis, angle and duration. A visible neutral action and controller shortcut remain available over the modal. There is no fake live dashboard or simulated sensor on Bench or Ground.

## Functional contract

- **52 editable properties across 9 sections** have one real `Rocket` state behind UI, file and renderer. Model validation rejects impossible ranges and dependent fit; undo/reset operate on that model. The custom insert is a coaxial cylinder/tube, not general-purpose CAD. The linked OBJ/ASCII-or-binary-STL reference is rendered as a visual comparison only and never contributes to mass or flight. The `.eul` v3 file saves template/user-design/old-unknown input origin and links a fixed-name sibling mesh, so missing external files must be reported rather than silently invented. The separately imported operator fin log cannot change the solver or grant an inspection pass.
- Approximate open-loop three-dimensional translation, orientation and angular rate support horizontal range, tilt/heading, wind, fixed gimbal assumptions, Mach, camera presets and timeline scrubbing. The reference drag, fin normal force, CP and damping are **not measured**. This model never commands an actuator. Recorded pressure/temperature/gyro/acceleration CSV uses a stationary-window pressure/gyro reference for **relative** barometric height and drifting sensor-axis attitude; legacy altitude/gyro CSV is also accepted. Neither is a live board connection. The candidate ESP32/STM32 Arduino `.ino` recorder is compile-only on representative cores, not a verified sensor or RF link.
- The manual Bench page can call only an injected `BenchControl`. The host preview injects **none**. A separate **in-app hardware profile** edits VID:PID, vendor interface, expected/auto bulk endpoints and four board-advertised pin IDs; it is stored outside `.eul`, never auto-connects, and edits neutralise/close the link. The Orbis adapter reads that runtime profile instead of compiling a guessed board ID into the PKG. With its gate **open**, a compatible board must identify, advertise its approved PWM pool and confirm a default-cancel logical pin mapping; its physical gate pin remains fixed in firmware. The user closes the gate and re-identifies before the fixed ±2°/150 ms manual pulse and its **separate** confirmation. Navigation out, controller loss and protocol failure close the link; the device must implement board-local neutral deadlines and have an independent physical servo-power cut-off. An ACK is receipt, not observed travel or safety. A firmware protocol and hardware-specific PWM/USB adapter remain prerequisites for each chip; there is no arbitrary universal GPIO driver.
- Numeric fields allow host typing and Enter/Esc, +/- and D-pad stepping; PS4 does **not** open an unusable keyboard. Save/load has a default-cancel unsaved-change guard. Menus, toolbar, tree selection, inspector, viewport controls, recorded-data scrubbing and Bench controls have keyboard/controller/mouse paths. The host browser is a **thin framebuffer/event/file transport**; it does not reimplement physics, UI or Orbis USB.

## Teaser direction

The 30-second host walkthrough uses **ENERGY 1 / RHYTHM 2 / MOTION 1**. Dark ink bookends frame the off-white native workbench; no dark-mode app is invented. The blue datum echoes the *model* silhouette, not a measured airframe. Four short chapters show Design inputs and an **empty** fin inspection, Ground with **no** sensor file, time-compressed **model** Flight, and Bench with **no** USB board. Every product frame is captured from the **current C++ host executable**, including Bench; no older screenshots, stock launch footage, physical readings or servo movement are substituted. The score is original non-diegetic audio, not sampled motor or actuator sound. The script regenerates video, poster and synced WebVTT from one storyboard: [`tools/make_teaser.py`](tools/make_teaser.py).

The [`anti-slop`](https://github.com/miqdadbadjuber/anti-slop) skill (including UI and code guidance) was used **during development**: the design read preceded implementation, techniques were justified by the work, then native hitbox/keyboard/controller and HTTP round-trip tests and rendered-frame inspections checked the actual controls. The static frame is 1280 × 720; this does not imply Orbis screen-reader integration or a console-runtime test. Evidence and unresolved boundaries: [`docs/workbench-audit.md`](docs/workbench-audit.md).
