# Workbench review: anti-slop Delivery Gate

Scope: the shared **native 1280 × 720 C++ UI** and its thin Linux framebuffer preview. [`DESIGN.md`](../DESIGN.md) records the design read and reasons before the bench panel was drawn. The [`anti-slop`](https://github.com/miqdadbadjuber/anti-slop) core, UI and code checks were applied **during** implementation, not just to a final screenshot. Web-only rules are interpreted at the preview boundary; they do not imply Orbis accessibility support or a responsive console display.

## Reproducible checks

| Check | Evidence |
| --- | --- |
| Functional tests | `make -j2 all test`: core model/mesh/CSV/file tests, 52/52 editable inspector fields, hitboxes, menu/toolbar, keyboard/controller focus, visual reference, playback, editable and atomically persisted Bench hardware profile, default-cancel confirmation/neutral, USB byte stream/selected composite descriptor/board mapping loopback, **STM32 device policy with fake HAL**, and 7 HTTP tests. Fakes are explicitly not hardware. |
| Build hygiene | `git diff --check` and `g++ -Wall -Wextra -Wpedantic` for host. The Orbis adapter was syntax-checked against OpenOrbis v0.5.4's Usbd/libusb declarations, not a generic host libusb. CI separately builds the ESP32-S3 reference with reserved, compile-only USB IDs. Full PS4 and firmware CI must run on **this pushed revision**; the prior green run does not cover the new profile/protocol changes. |
| Image inspection | `docs/assembly-host.png`, `docs/descent-host.png`, `docs/bench-host.png`, `docs/bench-setup-host.png`: generated by the shared executable at 1280 × 720. The profile hex editor and bench confirmation were also rendered and inspected locally. Clipped labels and a line abutting the status strip were shortened after pixel inspection. These images are **host output**; there is no photographed servo or PS4 frame. |
| Contrast | WCAG relative-luminance calculation from `app_draw.cpp`: ink on paper 12.23:1, muted on paper 6.52:1, ink on bench surface 11.13:1, blue on selection 5.75:1, white on blue 7.03:1. These are source-color checks, not TV calibration. |

**Open boundaries:** the flight model uses assumed coefficients and cannot certify stability or safety. The USB bench code and ESP32-S3 reference firmware require an actual authorized VID/PID, board-approved PWM/gate wiring, flash on that exact board, independent physical power cut-off, instrumented PWM/neutral tests and console verification. The STM32 portable adapter has fake-HAL tests, **not** a flashable board image; a specific STM32's USB stack and PWM timers must be integrated separately. Neither chip is automatically controllable without matching firmware. LoRa and live gyro/altitude are not implemented. Host fakes, host frames and a PKG integrity check cannot resolve those boundaries.
