# EuloLab: engineering maturity review

This review supersedes the older **5.4/10 teaser-era snapshot**. It evaluates the current software and what has **actually been verified**, not the quality of the promotional video, rocket flight safety, or a measured prediction-accuracy score. A passing CI check must correspond to the **current PR head**; a compiled PS4 package or Arduino sketch is not a console, USB, sensor, radio or servo test.

**Scale:** 0 = absent; 5 = useful host prototype with major target-hardware gaps; 10 = the stated use case validated on the *identified* intended hardware with traceable independent measurements. Ratings are subjective, in half-point steps, with equal weight. They are **not** permission to build, energize, fly or launch a rocket.

## Gates to an evidence-backed 7, then 10

1. Identify the actual ESP32 and STM32 variants, BMP3xx/LSM6DSOX modules, radio and servo parts, wiring, core versions, permitted RF band and instruments. The checked-in `.ino` intentionally does **nothing** until configuration is reviewed; do not flash CI's illustrative build flags to unknown boards.
2. Collect unaltered, timestamped **real** fin-caliper/angle log(s) and a stationary-plus-known-motion sensor recording, with the operator, instrument, fixture/datum, uncertainties and physical reference readings. The software can import these, but there are **no such user files** today. Compare independently measured mass/CG and a justified CP estimate with the model; revise or reject the assumptions.
3. For *each named board*, demonstrate I²C disconnect fail-closed behaviour, serial rates and pressure/gyro/accel comparison; separately test two real LoRa radios/antennas and legal RF conditions. No GPS is in scope now. See [Arduino setup](../firmware/arduino/EuloRecorder/README.md) and [ground procedure](ground-calibration.md).
4. Develop and instrument a distinct, board-specific **Arduino-compatible FF/45/55 vendor-bulk EuloBench port** if the user requires `.ino` for bench hardware. The current Arduino core defaults do not meet this descriptor. With a disconnected igniter and independent servo power cut, capture actual USB descriptors, 50 Hz pulses, neutral and travel on an unloaded rig. A USB ACK alone is never travel evidence.
5. Run the app on a real console: inspect graphics/input/storage, libusb enumeration and fault handling. Evaluate usability and limits against the actual instruments. Independent engineering/range review is still required before any launch-related claim; model predictions must not be promoted to certification.

These gates require **physical equipment and its operator**. They cannot be completed by CI, a generated data file, a presentation video or guessing an unknown board pinout.
